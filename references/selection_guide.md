# 精華挑選準則

（通用準則。甲方專屬偏好見 `client_style.md`，兩者衝突時以 client_style 為準。）

## 先分清楚兩種成品

| | 直式短片 | 橫式精華 |
|---|---|---|
| 長度 | 18–35 秒 | 2–4 分鐘（要素多可延長） |
| 核心 | 一個爆點 | 一個話題的完整起承轉合 |
| 開頭 | 爆點盡量在前 5–10 秒，鋪陳越短越好 | 可以有 5–20 秒鋪陳，讓觀眾知道在做什麼 |
| 結尾 | 停在反應最高點後 0.5–1.5 秒 | 收在事件結束、主播的總結或吐槽 |
| 剪接 | 盡量單一段；最多 2–3 段 | 可多段跳剪，剪掉等待、讀取、重複嘗試 |

同一事件常常兩種都能做：橫式放完整過程，直式只取最高潮。

## 起承轉合（橫式每支都要有）

- **起**：話題怎麼開始的。主播提出一件事、遇到一個狀況（「我先去倒杯水，等我一下」）。
- **承**：事情發展、聊天室加入、狀況變嚴重。
- **轉**：爆點、反轉、被吐槽、出乎意料的一句話（聊天室：「主播沒有資格喝水」）。
- **合**：收尾的總結、吐槽或金句（回來後自己吐槽「這水喝得好貴」）。
- 候選表要寫出這四句的代表台詞與時間。寫不出「轉」的，通常撐不起一支橫式，改做 Shorts 或放棄。
- 中間沒有笑點的部分盡量剪短，笑點之間的空白目標 20–30 秒以內。

## 遊戲直播：什麼值得剪

強（優先）：
- 意外死亡、翻車、被嚇到、尖叫，以及之後的反應
- 一直失敗後終於成功（橫式最好，直式取「成功那一刻」）
- Bug、穿模、詭異的遊戲現象
- 主播對遊戲劇情或角色的強烈反應、吐槽
- 和聊天室互動產生的笑點（被觀眾吐槽、被指揮錯）

弱（通常跳過）：
- 單純操作好但沒有反應
- 聊天室爆量但原因是抽獎、宣傳、超級留言感謝念名
- 需要大量前情才看得懂的劇情段落（直式尤其不行）

## 雜談：什麼值得剪

- 有起承轉合的生活小故事（橫式）
- 一句話就能成立的神回覆、反差發言、自爆（直式）
- 回答棉花糖／問題時的意外答案
- 唱歌片段要小心：有版權的歌曲可能被 Content ID 認領，標註給使用者自行判斷

## 讀訊號的方法

- 聊天室爆量通常落後事件 5–20 秒（直播延遲＋打字時間），事件在 peak 之前找。
- `audio` 高、`chat` 低：可能只是遊戲音效或背景音樂，看逐字稿和截圖確認。
- `chat` 高、`audio` 低：可能是好笑的一句話（雜談常見），也可能只是開台打招呼／下播道別（通常跳過）。
- 開台前 10 分鐘與下播前 5 分鐘的爆量多半是打招呼，除非內容本身好笑。
- 訊號分數只是篩選工具。逐字稿讀起來不好笑就不要選，訊號低但內容好就要補進來。

## 決定精確進出點

- **進點**：在鋪陳句開頭前 0.3–1 秒。不要切在句子中間。
- **出點**：反應結束後 0.5–1.5 秒；如果主播馬上補一句吐槽，留到那句結束。
- 用逐字稿的時間戳決定，不要直接用 peak 秒數。
- 直式如果鋪陳太長，考慮「倒敘開場」：在最前面放 2–3 秒的最高潮片段，再接正常順序（在 selections 用兩個 segments 表達，並在候選清單註明）。
- 逐字稿不一定正確（遊戲配樂、尖叫、唸聊天室都會讓 Whisper 出錯或漏字）。剪點附近的句子讀起來不通順時，用前後的時間戳和截圖交叉確認，並在候選表註明「剪點需人工確認」。

## 信心標示

- 高：訊號強＋逐字稿明確好笑／畫面確認
- 中：其中一項強，另一項不確定
- 低：只有訊號或只有內容，請使用者自己看一下

## 標題與說明欄（台灣 YouTube 風格）

- 標題 15–30 字，直接講發生了什麼或主播的一句金句，可用【】標註主播名或遊戲名。例如：「【主播名】被小怪偷襲暴斃的瞬間 笑死」
- 短片標題更短，最重要的詞放前面。
- 不要誇大內容中沒發生的事。
- 說明欄：一句情境說明 → 原直播連結（留位置給使用者填）→ 主播頻道 → hashtag（#主播名 #遊戲名 #Vtuber #台V）。
